# TradingBuddy 访客自带密钥与 AI 开关设计

日期：2026-09-20

## 1. 目标

在保留 TradingBuddy 公开信息收集能力的前提下，将 AI 功能改为“访问者自带密钥、浏览器本地保存、服务器仅临时调用”。

本次交付包含：

- 左上角品牌从“图标 + 动态”改为“图标 + TradingBuddy”，桌面和手机端均显示完整名称；
- 设置页增加 AI 分析开关和通用 OpenAI 兼容配置；
- AI 默认关闭，关闭时只展示不依赖 AI 的行情、事件、重要性和来源能力；
- 每位访问者必须配置自己的 API Key 才能启用 AI；
- API Key、AI 结果和对话仅保存在当前浏览器；
- 在现有卡片引导中补充 AI 配置位置与启用后的效果；
- 服务端不再持久化新的 AI 分析或对话。

## 2. 非目标

本次不实现：

- 用户注册、登录和跨设备同步；
- 服务端托管或共享 API Key；
- AI 结果在不同浏览器之间同步；
- 公网多用户的资产、自选和人工判断隔离；
- AI 判断草稿的浏览器本地化改造。

现有 AI 判断草稿入口在本次界面中隐藏，相关代码和历史数据不删除。恢复该能力需要先完成账号隔离，或将整个判断草稿流程迁移到浏览器本地。

## 3. 访问者体验

### 3.1 品牌区

顶部左侧固定显示现有图标和 `TradingBuddy`。窄屏不隐藏品牌文字，而是压缩中间标的选择器并对标的名称使用省略号，保证右侧操作按钮仍可点击。

### 3.2 AI 默认关闭

首次访问和未保存配置时，AI 开关为关闭状态。页面保留：

- 标的管理；
- 行情快照和图表；
- 重要性时间线；
- 公开动态、公告、新闻和来源详情；
- 数据刷新；
- 研究档案中的“数据”和“来源”。

页面隐藏：

- “生成分析”和分析展开入口；
- 快捷追问；
- 底部聊天输入框；
- 推断链及服务器历史 AI 消息；
- AI 判断草稿入口；
- 研究档案中的 AI 推断相关页面。

动态卡片的状态文案改为“信息源已收集”，不再展示“是否影响原判断”等需要模型判断的表述。

### 3.3 设置页

设置页增加“AI 分析”区域：

- AI 分析开关，默认关闭；
- API Key 密码输入框，支持显示和隐藏；
- 模型名称，必填；
- API 地址，选填；留空时使用 `https://api.openai.com/v1`；
- “保存并启用”主操作；
- “清除本地 AI 配置”危险次操作；
- “重新查看 AI 使用说明”入口；
- “配置和分析结果仅保存在当前浏览器”的固定说明。

开启 AI 必须同时满足：API Key 非空、模型名称非空、API 地址格式合法。关闭开关只隐藏 AI 能力并保留配置；清除操作会删除配置、所有本地 AI 结果和 AI 引导状态。

### 3.4 AI 启用状态

启用后恢复：

- 事件“生成分析”；
- 快捷追问；
- 底部聊天输入框；
- 事实、推断、未知和核验建议；
- 本地 AI 对话和分析历史。

AI 结果按标的保存在当前浏览器。每个标的最多保存最近 50 条消息和最近 20 次分析，超出后删除最早记录，避免无限占用浏览器存储。

## 4. 引导设计

沿用现有高亮目标、遮罩和卡片式引导，不增加独立欢迎弹窗。

### 4.1 首次访问引导

AI 关闭时使用信息源版本的引导步骤：

1. 选择标的；
2. 查看行情和公开动态；
3. 查看重要性时间线与来源；
4. 查看研究档案中的数据和来源；
5. 高亮右上角设置按钮，说明 AI 默认关闭、配置路径和启用效果。

最后一步提供“打开 AI 设置”，结束引导并直接打开设置页的 AI 区域。跳过引导不会启用 AI。

### 4.2 首次启用 AI 引导

访问者首次保存并启用 AI 后，关闭设置面板并运行两步补充引导：

1. 高亮“生成分析”，说明结果会区分事实、推断、未知与证据；
2. 高亮聊天输入框，说明可围绕当前标的和证据继续追问，并提示结果只保存在当前浏览器。

设置页的“重新查看 AI 使用说明”根据当前开关状态启动对应版本的引导。

## 5. 浏览器本地数据

使用带版本号的 `localStorage` 键：

```text
tradingbuddy.ai.config.v1
tradingbuddy.ai.workspace.v1
tradingbuddy.tour.sources.v2
tradingbuddy.tour.ai.v1
```

配置结构：

```json
{
  "enabled": true,
  "apiKey": "访问者密钥",
  "model": "gpt-4.1-mini",
  "baseUrl": "https://api.openai.com/v1",
  "updatedAt": "ISO-8601 时间"
}
```

工作区按标的 ID 保存消息和分析。读取本地数据时必须校验类型和长度；解析失败时忽略损坏数据并回退到空状态，不阻塞信息源页面。

## 6. AI 请求与服务端边界

### 6.1 请求配置

AI 请求通过以下请求头携带访问者配置：

```text
X-TB-API-Key
X-TB-Model
X-TB-Base-URL
```

非 AI 接口不接收这些请求头。Nginx 和应用日志不得输出请求头或请求体。

研究分析和聊天继续使用现有 SSE 响应。聊天请求体增加最多 6 条本地最近消息，单条内容不超过 2,000 字符，供模型维持上下文。

### 6.2 请求级模型客户端

AI 服务不再从全局 `settings.openai_api_key` 创建客户端。每次 AI 请求解析并校验请求头，创建只在该请求内存在的配置对象和模型客户端，响应结束后不保存引用。

研究和聊天路由不再：

- 向 `analyses` 表写入结果；
- 向 `messages` 表写入对话；
- 从公共 `messages` 表读取历史上下文。

资产概览也不再向页面返回服务器历史 AI 消息。已有数据库记录保留，但不在公网界面展示。

AI 判断草稿生成接口在浏览器本地模式下返回明确的不可用错误，防止绕过隐藏入口后继续向公共数据库写入 AI 草稿。

### 6.3 API 地址安全

API 地址规则：

- 空值映射到 `https://api.openai.com/v1`；
- 仅允许 `https`；
- 禁止 URL 用户名和密码；
- 主机名解析结果必须全部是公网地址；
- 拒绝 loopback、private、link-local、multicast、reserved 和 unspecified 地址；
- 拒绝 `localhost` 和 `.local` 主机名；
- 模型客户端不跟随 HTTP 重定向；
- API Key、模型名和地址设置长度上限。

这些限制用于降低服务端请求伪造风险，同时保留 OpenAI 兼容公网服务能力。

## 7. 错误处理

前端将 AI 错误映射为可执行提示：

- 缺少配置：打开设置并定位到 AI 区域；
- 401/403：密钥无效或没有模型权限；
- 429：供应商限流或额度不足；
- 超时：提示稍后重试，保留来源页面；
- API 地址被拒绝：说明仅支持 HTTPS 公网地址；
- 模型输出校验失败：保留原始来源，不生成替代结论；
- `localStorage` 不可用：不启用 AI，并说明浏览器需要允许本地存储。

任何 AI 错误都不得影响行情、事件、重要性或来源查看。

## 8. 浏览器安全响应头

应用增加以下响应策略：

- `Content-Security-Policy`：脚本仅允许同源，连接仅允许同源，禁止对象和外部 frame；
- `X-Content-Type-Options: nosniff`；
- `Referrer-Policy: strict-origin-when-cross-origin`；
- `Permissions-Policy`：关闭页面不需要的敏感能力；
- `frame-ancestors 'none'`，防止页面被嵌入。

页面不引入第三方脚本。由于现有界面包含少量内联样式，CSP 的样式规则暂时允许同源和内联样式，脚本规则不允许内联脚本。

## 9. 测试与验收

### 9.1 后端自动测试

- 请求级配置必填项和长度校验；
- OpenAI 默认地址和兼容地址；
- 内网、localhost、非 HTTPS 和带凭据 URL 被拒绝；
- AI 路由缺少配置时返回明确错误；
- 研究和聊天成功后 `analyses`、`messages` 记录数不增加；
- 聊天上下文数量和长度受限；
- AI 判断草稿生成在该模式下不可用；
- 安全响应头存在。

### 9.2 前端自动测试

- 品牌文字为 `TradingBuddy`；
- AI 默认关闭；
- 关闭时不存在分析、追问、输入框和 AI 草稿入口；
- 配置保存、刷新恢复、关闭保留和清除删除；
- 启用前校验 Key、模型和地址；
- 本地消息与分析按标的隔离并执行数量上限；
- 信息源引导不定位隐藏元素；
- 首次启用后运行 AI 补充引导。

### 9.3 部署验收

- 桌面和手机宽度下品牌、标的选择器和右侧按钮不重叠；
- HTTPS 首页和 `/api/health` 正常；
- AI 关闭时刷新行情和来源正常；
- 使用访问者测试密钥完成一次真实流式分析和一次追问；
- 清除配置后页面立即回到信息源模式；
- 浏览器 A 的配置和结果不会出现在浏览器 B；
- systemd 服务和 Nginx 保持 active。

## 10. 发布与兼容

本次不删除 SQLite 表和历史数据，不需要数据库破坏性迁移。发布时更新静态资源版本参数，避免浏览器继续使用旧 JavaScript 和 CSS。

服务器 `.env` 中现有模型配置不再作为公网访问者 AI 的后备配置，避免访客意外消耗服务器所有者的额度。健康检查改为报告 `visitor_ai_supported`，不暴露任何访问者配置。
